# RANCIMATE on GaggiMate 1.10.0

Base: upstream tag `v1.10.0`, commit `34bf9fc5f6cf89c9929636fc23092b75284092f9`.
Firmware version: upstream tag plus `-rancimate` (`v1.10.0-rancimate`), generated by
`scripts/auto_firmware_version.py`.

Design and rationale of the thermal control: [CONCEPT.md](CONCEPT.md).

## Additions

### AMOLED screensaver and branding

- Screensaver: `src/display/ui/default/DefaultUI.cpp` and `.h`. After the timeout in
  standby, a black screen shows the clock, status icons, a tap hint and a moving cup
  logo. A tap ends the screensaver. Animation: 500 ms fade-in, 4 s visible, 500 ms
  fade-out, then new positions.
- Timeout: `src/display/core/Settings.h` and `.cpp`, `src/display/plugins/WebUIPlugin.cpp`
  and `web/src/pages/Settings/tabs/GeneralTab.jsx`. Default 300 seconds; `0` disables
  the screensaver. The API uses seconds, the stored setting milliseconds.
- Standby wordmark: `eez-ui/icons/standby-logo.png`,
  `src/display/ui/default/eez/images/ui_image_standby_logo.c`,
  `src/display/ui/default/eez/screens.c` and `eez-ui/gaggimate.eez-project`. The bitmap
  is 392 × 53 pixels like the original; RANCI is bolder than MATE. The separate logo of
  the welcome screen is not affected.
- Screensaver cup logo: `src/display/ui/default/eez/images/ui_image_cup_rm_screensaver.c`.
- Web wordmark: `web/src/components/Navigation.jsx` and `web/index.html`. Translations
  live in `web/src/locales/`.
- README banner: `docs/assets/rancimate-logo.png`.

Graphic files and their LVGL C bitmaps must be kept in sync. `images.h` and `images.c`
register the image resources.

The older tool `legacy/heatup_logger.py` records status data over the WebSocket; it has
not been verified against 1.10.

### PID advanced for isolated boilers

Web UI: *Settings → Machine → PID advanced for isolated boilers*.

- **Master switch** (`thermalAdvancedEnabled`, NVS `ta_en`). Off = the controller behaves
  exactly like upstream; all new fields are ignored.
- **Controller** (`lib/GaggiMateController/src/peripherals/Heater.*`,
  `lib/NayrodPID/src/SimplePID/*`): integral band, integral authority limit with state
  back-calculation, heat-up power cap (lifted while water is drawn), configurable
  feedforward thermal model and feedforward factor, brew mode (integral frozen during a
  shot and for `brewHoldoffS` afterwards, P factor), fixed feedforward safety scaling
  (it jumped from 1.0 to 0.7 just below setpoint).
- **Protocol**: `HeaterSettings` fields 10–20, `PROTOCOL_VERSION` 17. **Always flash
  display and controller together**, otherwise the version check keeps the heater locked.
- **Kff**: if the stored Kff is 0, the display sends `1000 / heater wattage` in advanced
  mode (default 1100 W).
- **Autotune Watchdog** (`src/display/plugins/ThermalWatchdogPlugin.*`, logic in
  `src/display/core/thermal/ThermalTuner.h`): measures every shot 60 s before, during and
  180 s after the draw, and every heat-up. With the watchdog on, each shot outside the
  allowed spread (default 2 °C) adjusts the feedforward factor, P factor / hold time,
  integral limit, approach power or integral band in small, bounded steps. With the
  watchdog off the values stay as they are and can be edited; shots are still measured.
  While the watchdog is on, the API ignores posted control parameters.
- Not evaluated: utility profiles (flush, cleaning), shots shorter than 10 s or longer
  than 120 s, shots without a stable minute before them, shots more than 5 K away from
  the setpoint.
- Tests: `env/bin/pio test -e native -f test_thermal_shaping`.

## Building

Requirements: Python with `venv`, Node.js 22+ and npm. The local Python environment
lives in `env/`, Node dependencies in `web/node_modules/`. PlatformIO also uses its
packages in `~/.platformio/`. If the environments are missing, restore them from the
manifests:

```sh
python3 -m venv env
env/bin/python -m pip install -r custom/requirements-build.txt
npm --prefix web ci
```

After changes to the web UI, it must be embedded **before** the firmware build; a plain
`npm run build` is not enough:

```sh
npm --prefix web run build
gzip -f web/dist/assets/*.js web/dist/assets/*.css web/dist/*.html
python3 scripts/embed_webui.py --src web/dist --out src/display/webassets
env/bin/pio run -e display
```

Result: `.pio/build/display/firmware.bin`. Without an embedded web UI, PlatformIO builds
an empty placeholder instead.

### Release files

A release carries the same files as an upstream GaggiMate release:

| File | Source |
|---|---|
| `board-{bootloader,partitions,firmware}.bin` | `pio run -e controller` |
| `display-{bootloader,partitions,firmware}.bin` | `pio run -e display` |
| `display-headless-{bootloader,partitions,firmware}.bin` | `pio run -e display-headless` |
| `display-filesystem.bin`, `display-headless-filesystem.bin` | `pio run -t buildfs -e display` |
| `app-web.zip`, `app-web.json` | `GITHUB_REPOSITORY=OMNIDROID2995/rancimate web/scripts/package-app-bundle.sh <out> <tag>` |

The release tag must be the firmware version (`v1.10.0-rancimate`): the OTA updater
reads the version from the tag of the latest release.

## Archived earlier state

`legacy/legacy-changes.patch.gz` contains the tracked changes of the earlier checkout,
including binary changes. `legacy/legacy-new-files.tar.gz` contains its four untracked
extension files. Base is commit `97afdb7d1d89c115df108350e228d0af11f67df4`; the patch is
not meant for 1.10. The original screensaver notes and logo previews are in `legacy/` as
well.

To restore it, check out the old commit in a **separate** checkout, apply the unpacked
patch there with `git apply --binary` and unpack the archive of new files into that
checkout. Do not overwrite the 1.10 changes.
